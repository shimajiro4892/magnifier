# 拡大鏡 (Magnifier)

macOS ネイティブの常駐型（メニューバー）拡大鏡アプリです。
**マウスの特定ボタンを押している間だけ**、カーソル周辺を拡大するレンズを表示します。
ScreenCaptureKit で画面を直接キャプチャして最前面のオーバーレイに描画するため、**どんなアプリの上でも**動作します。

## 特徴

- **マウスボタンを押している間だけ拡大**（既定: 中ボタン / ホイールクリック）。離すと即座に消えます
- **どんなアプリの上でも動作**（フルスクリーンアプリ、別スペース、マルチディスプレイを含む）
- **拡大する範囲・倍率・形状を設定で変更**（円 / 角丸長方形 / 長方形）
- クリックは背面のアプリにそのまま届きます（イベントを奪いません）
- Dock に出ないメニューバー常駐アプリ
- キャプチャはボタンを押している間だけ動くので、通常時は消費電力ゼロ

## 動作要件

| 項目 | 要件 |
| --- | --- |
| OS | macOS 14.0 以降 |
| ビルド | Xcode 16 以降（実行のみなら不要） |
| 権限 | 画面収録（Screen Recording） |

## ビルドと実行

### Xcode で実行

1. `Magnifier.xcodeproj` を開く
2. スキーム `Magnifier` を選んで Run（⌘R）

### コマンドラインで実行

```sh
./scripts/build.sh              # Debug ビルド
./scripts/build.sh --release    # Release ビルド
./scripts/run.sh                # ビルドして起動（起動中のインスタンスは再起動）
```

## 初回セットアップ（画面収録の許可）

拡大鏡は画面をキャプチャするため、macOS の「画面収録」許可が必要です。

1. アプリを起動すると、システムの許可ダイアログが表示されます
2. **システム設定 → プライバシーとセキュリティ → 画面収録** で「拡大鏡」をオンにします
   （設定画面の「システム設定を開く」ボタンからも移動できます）
3. アプリを再起動します（設定画面の「再起動」ボタン、または `./scripts/run.sh`）

許可が無い状態でボタンを押すと、案内ダイアログが表示されます。

## 使い方

1. メニューバーの 🔍 アイコンが表示されていれば起動中です
2. **中ボタン（ホイールクリック）を押している間**、カーソル周辺がレンズで拡大されます
3. ボタンを離すとレンズが消えます
4. 終了はメニューバーのアイコン →「終了」

動作確認用に、ボタンを押さずに 8 秒間だけ強制表示する起動オプションもあります。

```sh
open -n build/Build/Products/Debug/Magnifier.app --args --activate
```

## 設定項目

メニューバーのアイコン →「設定…」から変更できます（変更内容は自動保存されます）。

| セクション | 項目 | 既定値 | 説明 |
| --- | --- | --- | --- |
| 動作 | 拡大鏡を有効にする | オン | 一時的に無効化できます |
| 動作 | 起動ボタン | 中ボタン | 左 / 右 / 中 / ボタン4 / ボタン5 |
| 拡大する範囲 | 横 / 縦 | 180 × 120 pt | **元の画面上で**拡大する範囲の大きさ |
| 拡大する範囲 | 倍率 | 2.5 倍 | 1〜10 倍 |
| 表示 | 形状 | 角丸長方形 | 円 / 角丸長方形 / 長方形 |
| 表示 | カーソルを拡大表示に含める | オン | レンズ内にカーソルを描画するか |
| 表示 | なめらかに拡大 | オン | オフにするとドット感のある拡大 |
| 表示 | 枠線を表示 | オン | レンズの縁取り |
| 表示 | 画面の外にはみ出さない | オン | 画面端でレンズと拡大範囲をクランプ |
| 表示 | 表示位置のずれ X / Y | 0 pt | レンズをカーソルから離して表示 |
| キャプチャ | フレームレート | 60 fps | 30 / 60 / 120 fps |

レンズの大きさは「範囲 × 倍率」です（180 × 120 pt・2.5 倍 → 450 × 300 pt のレンズ）。

## 仕組み

```
  マウスボタン押下
        │
        ▼
  MouseButtonMonitor ── グローバルイベントモニタ（イベントは奪わない）
        │
        ▼
  ScreenCaptureEngine ── ScreenCaptureKit でカーソルのあるディスプレイをキャプチャ
        │                   （押下中のみ。IOSurface をそのまま受け取る）
        ▼
  LensRenderer ── CALayer.contents に IOSurface を渡し、
        │          contentsRect でカーソル周辺を切り出して GPU で拡大
        ▼
  OverlayWindow ── メニューバーより上のクリックスルーウィンドウにレンズを描画
                   （CADisplayLink で最大 120Hz 追従）
```

設計上のポイント:

- **拡大処理は GPU**。毎フレームの画像変換をせず、`CALayer.contents` に IOSurface を直接渡して
  `contentsRect`（正規化座標）で切り出すだけなので軽量です
- **レンズ自身はキャプチャから除外**（`NSWindow.sharingType = .none` と `SCContentFilter` の除外指定）。
  映り込んで無限鏡にならないようにしています
- **静的画面でも正しく追従**。キャプチャは画面内容が変わった時だけ届きますが、
  フル解像度のフレームを保持して切り出し位置だけを動かすため、カーソル移動に追従します
- **マルチディスプレイ対応**。カーソルのあるディスプレイだけをキャプチャし、
  別ディスプレイへ移動するとウィンドウごと移動します

### 座標系の注意

レイヤーの座標系は下原点（非フリップ）のため、`contentsRect` の y 原点は画像の**下端**になります。
アプリ側では「画面座標（上原点）の切り出し矩形」から `y = 1 - (y + height)` で変換しています。
この変換は `Tools/verify-crop-math.swift` で検証済みです。

## 検証

```sh
swift Tools/verify-crop-math.swift
```

4 象限に色分けしたテスト画像を使い、以下を検証します。

- レイヤー内容が上下反転していないこと
- `contentsRect` の原点の扱い（上原点への変換が正しいこと）
- カーソル位置に応じた切り出しが正しいこと（画面端のクランプを含む）
- `CALayer.render(in:)` と AppKit の `cacheDisplay` の 2 経路で一致すること
- ScreenCaptureKit が渡すのと同じ **IOSurface を contents にした場合**も正しいこと

## 署名について

`scripts/build.sh` はキーチェーンにある **Apple Development 証明書**を自動で見つけて署名します。
証明書で署名しておくと、**画面収録の許可がリビルド後も保持されます**（ad-hoc 署名だと毎回リセットされます）。

- 証明書が見つからない場合は自動的に ad-hoc 署名（`-`）にフォールバックします。
  その場合、リビルドのたびに画面収録の許可をやり直す必要があります。
- 証明書を明示したい場合は `CODE_SIGN_IDENTITY` を渡してください。

  ```sh
  CODE_SIGN_IDENTITY="Apple Development: your@email (TEAMID)" ./scripts/build.sh
  ```

- Xcode の GUI からビルドする場合は、プロジェクトの Signing & Capabilities で
  自分のチームを選び直してください（プロジェクトには開発機の証明書ハッシュを設定してあります）。

## 既知の制約

- 左ボタン / 右ボタンを起動ボタンにした場合も、クリックは背面アプリにそのまま届きます
  （イベントを消費しないため。右クリックメニューなども通常どおり表示されます）
- アプリアイコンは未設定です（既定のアイコン）
- ログイン時の自動起動、キーボードショートカットは未実装です
